# verl + Megatron + vLLM + GRPO 参数速查表

> 对应实例：Qwen3-0.6B（文本）+ GSM8K 子集 + GRPO，单卡 A800
> 入口脚本：`scripts/run_grpo_qwen35_0.8b.sh`
> 成功日志：`logs/run_20260831_104244/train.log`

---

## 0. 这份文档怎么用

- 想改哪个环节的参数，直接跳到对应章节，改完重跑。
- 参数名都是"点分路径"，对应 verl 配置树里的层级，**不能写错层级**，否则 verl 会报 `key not found`。
- 命令行临时改参数：`bash scripts/run_grpo_qwen35_0.8b.sh <参数1=值> <参数2=值> ...`
- 永久改：编辑 `scripts/run_grpo_qwen35_0.8b.sh` 里对应那一行。

---

## 1. 一次实验怎么做

```bash
# 从 ~/zymo 直接跑（脚本自带 cd，任意目录都行）
bash grpo_qwen3.5_0.8b/scripts/run_grpo_qwen35_0.8b.sh

# 实验常用：只跑 8 步、只存 1 个 checkpoint（避免生成 100 多 G 文件）
bash grpo_qwen3.5_0.8b/scripts/run_grpo_qwen35_0.8b.sh trainer.total_training_steps=8 trainer.save_freq=8

# 边跑边看日志
tail -f grpo_qwen3.5_0.8b/logs/run_*/train.log
```

耗时参考：启动约 4–6 分钟；每步约 38 秒；32 步全程约 25 分钟，8 步实验约 10 分钟。

## 2. 环境变量（脚本开头）

| 变量 | 本次值 | 含义 |
|---|---|---|
| `CUDA_VISIBLE_DEVICES` | `0` | 用哪块 GPU（0 = 第一张 A800） |
| `CUDA_DEVICE_MAX_CONNECTIONS` | `1` | 开启 Megatron 通信与计算重叠（官方推荐） |
| `VLLM_USE_V1` | `1` | 使用 vLLM 的 V1 引擎 |
| `VERL_USE_UV` | `0` | 不用 uv 启动（我们用 pip 装的 verl 环境） |

---

## 3. 启动入口参数

| 参数 | 含义 |
|---|---|
| `--config-path=config` | 配置目录（项目里的 `config` 是到 verl 安装目录的符号链接） |
| `--config-name=ppo_megatron_trainer` | 用 Megatron 训练引擎的配置（在默认配置基础上叠加 `model_engine=megatron`） |

> 前缀 `++` 表示"往配置里**新增**一个原本不存在的键"（如 `override_transformer_config.masked_softmax_fusion`）。普通 `=` 是覆盖已有键。

---

## 4. 数据参数（`data.*`）

| 参数 | 本次值 | 含义 / 备注 |
|---|---|---|
| `data.train_files` / `data.val_files` | parquet 路径 | 训练/验证数据，格式见 `scripts/prepare_gsm8k.py` |
| `data.return_raw_chat` | `True` | 用模型自带 chat 模板包装 prompt（消息列表） |
| `data.train_batch_size` | `32` | 每个训练步取 32 条 prompt；**显存的主要开关** |
| `data.max_prompt_length` | `512` | 输入最长 token 数，超长被过滤或报错 |
| `data.max_response_length` | `512` | 模型回答最长 token 数，决定 rollout 长度上限 |
| `data.filter_overlong_prompts` | `True` | 过滤超长 prompt |
| `data.truncation` | `error` | 超长时直接报错（另一种是 `left`/`right` 截断） |

数据准备脚本里的参数（`scripts/prepare_gsm8k.py`）：

| 参数 | 本次值 | 含义 |
|---|---|---|
| `--train_samples` | `512` | 训练集条数（改小 = 每轮步数变少 = 实验更快） |
| `--test_samples` | `128` | 验证集条数 |
| `--dataset` | `openai/gsm8k` | 数据源，决定 reward 判分器（`data_source` 列） |

---

## 5. 模型参数（`actor_rollout_ref.model.*`）

| 参数 | 本次值 | 含义 / 备注 |
|---|---|---|
| `model.path` | `models/Qwen3-0.6B` | 初始权重（HF 格式本地路径） |
| `model.use_fused_kernels` | `False` | 关掉 fused 内核（本机没装 TE/Apex，开着会崩） |
| `model.use_remove_padding` | `False` | 不用 packed sequence（本地注意力不支持，开着会崩） |

---

## 6. Actor 训练参数（`actor_rollout_ref.actor.*`）

| 参数 | 本次值 | 含义 / 备注 |
|---|---|---|
| `actor.optim.lr` | `1e-6` | 学习率。RL 一般很小（1e-6 ~ 1e-7） |
| `actor.ppo_mini_batch_size` | `16` | 32 条样本切成 16 的小批更新（更新次数 = batch/mini） |
| `actor.ppo_micro_batch_size_per_gpu` | `2` | 显存友好的微批大小，越小越省显存 |
| `actor.use_kl_loss` | `True` | 是否用 KL 惩罚防止模型偏离参考模型太远 |
| `actor.kl_loss_coef` | `0.01` | KL 惩罚权重；**实验重点**：改大 → 更保守，改小 → 更激进 |
| `actor.kl_loss_type` | `low_var_kl` | KL 变体（low_var_kl 数值更稳） |
| `actor.entropy_coeff` | `0` | 熵正则系数（鼓励探索用，通常 0） |
| `actor.megatron.tensor_model_parallel_size` | `1` | TP：张量并行（把一层拆到多卡） |
| `actor.megatron.pipeline_model_parallel_size` | `1` | PP：流水线并行（把层分段到多卡） |
| `actor.megatron.use_mbridge` | `True` | 使用 verl 的 bridge 机制（Megatron-Bridge 路径） |
| `actor.megatron.vanilla_mbridge` | `False` | 不用旧版 mbridge 后端（那套需要 Transformer Engine） |
| `++actor.megatron.override_transformer_config.masked_softmax_fusion` | `False` | 关掉 fused softmax（PyPI 版 megatron-core 缺编译扩展） |

> TP×PP 乘积 = 训练用的 GPU 数。单卡就是 1×1；想练多卡并行，把这俩改大即可（如 2 卡 TP=2，4 卡 TP=2×PP=2）。

---

## 7. Rollout 生成参数（`actor_rollout_ref.rollout.*`）

| 参数 | 本次值 | 含义 / 备注 |
|---|---|---|
| `rollout.name` | `vllm` | 生成引擎（必填，用 vLLM） |
| `rollout.tensor_model_parallel_size` | `1` | vLLM 侧的张量并行（生成用几张卡） |
| `rollout.gpu_memory_utilization` | `0.3` | vLLM 最多占 30% 显存（和训练共用一张卡时留空间） |
| `rollout.n` | `2` | **每个 prompt 生成几个回答 = GRPO 的"组大小"**。改大 → 组内比较更稳，但生成耗时线性增加 |
| `rollout.log_prob_micro_batch_size_per_gpu` | `2` | 算旧策略对数概率时的微批大小 |

---

## 8. Ref 参考模型参数（`actor_rollout_ref.ref.*`）

| 参数 | 本次值 | 含义 / 备注 |
|---|---|---|
| `ref.log_prob_micro_batch_size_per_gpu` | `2` | 参考模型算 logprob 的微批大小 |
| `ref.megatron.tensor_model_parallel_size` / `pipeline_model_parallel_size` | `1` / `1` | 参考模型的并行配置，一般和 actor 保持一致 |
| `ref.megatron.use_mbridge` / `vanilla_mbridge` | `True` / `False` | 同 actor 的 bridge 设置 |
| `++ref.megatron.override_transformer_config.masked_softmax_fusion` | `False` | 同上，环境适配 |

> ref 模型 = 训练开始时的"冻结副本"，用来算 KL，防止模型为了拿分开始说胡话。

---

## 9. 算法参数（`algorithm.*`）

| 参数 | 本次值 | 含义 / 备注 |
|---|---|---|
| `algorithm.adv_estimator` | `grpo` | **核心算法**。GRPO 用组内相对优势（比 PPO 省 critic） |
| `algorithm.use_kl_in_reward` | `False` | KL 不计入 reward（KL 通过 `kl_loss_coef` 单独惩罚） |

reward 怎么判分：数据里 `data_source=openai/gsm8k` → verl 自动用内置 gsm8k 判分器，检查回答里 `#### 答案` 是否与 `ground_truth` 一致。

---

## 10. Trainer 参数（`trainer.*` / 顶层）

| 参数 | 本次值 | 含义 / 备注 |
|---|---|---|
| `model_engine` | `megatron` | 训练引擎（Megatron；可选 fsdp 等） |
| `trainer.critic_warmup` | `0` | GRPO 不需要 critic，设为 0 |
| `trainer.logger` | `["console"]` | 日志输出（可加 `"wandb"`，需要 wandb 账号） |
| `trainer.project_name` / `experiment_name` | 见脚本 | 日志/checkpoint 的命名 |
| `trainer.n_gpus_per_node` | `1` | 每节点 GPU 数（和 `CUDA_VISIBLE_DEVICES` 对应） |
| `trainer.nnodes` | `1` | 节点数 |
| `trainer.total_epochs` | `2` | 总轮数（本实例 512 条 / 32 批 = 16 步/轮 × 2 = 32 步） |
| `trainer.total_training_steps` | 未设（None） | **实验利器**：直接限定总步数，如 `=8` 只跑 8 步 |
| `trainer.save_freq` | `2` | 每几步存一次 checkpoint（**每存一次约 8G，改大能省磁盘**） |
| `trainer.test_freq` | `1` | 每几步跑一次验证（产出 `reward/mean@1` 等） |
| `trainer.default_local_dir` | `checkpoints/smoke_gsm8k_qwen3_0_6b` | checkpoint 保存目录 |
| `hydra.run.dir` | `logs/run_<时间戳>` | 本次运行的日志目录（由脚本自动生成） |

---

## 11. 值得知道的默认行为

- **精度**：默认 bf16 训练（日志里 `params_dtype=torch.bfloat16`）。
- **checkpoint 体积**：每次保存约 8G（Megatron 权重 + 转回 HF 格式），`save_freq=2` 跑 32 步会产生约 130G，**实验时务必调大 save_freq 或删旧 checkpoint**。
- **日志看什么**：`step:N` 行里的 `reward/mean@1`（验证答对率）、`actor/loss`、`kl_loss`、`response_length/mean`、`timing_s/*`（各阶段耗时）。
- **本机环境限制**：没有 Transformer Engine，因此 `use_fused_kernels=False`、`use_remove_padding=False`、`masked_softmax_fusion=False` 这三个适配不能随意改回 True。

## 12. 新手实验组合（照抄即可）

```bash
# 实验 A：看 rollout.n（组大小）对生成耗时和 reward 的影响（8 步，不存 checkpoint）
bash grpo_qwen3.5_0.8b/scripts/run_grpo_qwen35_0.8b.sh actor_rollout_ref.rollout.n=4 trainer.total_training_steps=8 trainer.save_freq=1000

# 实验 B：看 kl_loss_coef（KL 惩罚）对训练稳定性的影响
bash grpo_qwen3.5_0.8b/scripts/run_grpo_qwen35_0.8b.sh actor_rollout_ref.actor.kl_loss_coef=0.1 trainer.total_training_steps=8 trainer.save_freq=1000

# 实验 C：看 batch size 对显存和每步耗时的影响
bash grpo_qwen3.5_0.8b/scripts/run_grpo_qwen35_0.8b.sh data.train_batch_size=64 trainer.total_training_steps=8 trainer.save_freq=1000
```

每次跑完对比 `logs/run_*/train.log` 里对应指标即可。一次实验约 10 分钟。
